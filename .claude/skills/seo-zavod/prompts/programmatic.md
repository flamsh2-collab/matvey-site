# programmatic.md — программный слой (длинный хвост из данных)

Самый мощный рычаг хвоста: страницы из ДАННЫХ, а не из текста. Один тип страниц × таблица
комбинаций → Astro `getStaticPaths` генерирует все страницы одним билдом. Так pleada.shop
делает 64 000 страниц (ЖК × район × метро × застройщик). В курсе — минимальная версия.

```
Сделай программный тип страниц «{ТИП}» (напр. услуга × район).

1. ДАННЫЕ: создай/возьми src/data/{name}.json — список объектов с полями для страницы
   (напр. {usluga, rajon, h1, intro, price_from}). Заполни из company_voice.md и research.
2. ШАБЛОН: src/pages/{usluga}-{rajon}.astro с export getStaticPaths():
   - читает src/data/{name}.json
   - возвращает paths по каждой комбинации (params + props)
   - рендерит страницу: H1 с гео-ключом, TLDR, блок услуги, FAQ, CTA, JSON-LD (Service/LocalBusiness), перелинковка на блог.
3. SEO/GEO: уникальные title/description на комбинацию, sitemap подхватит автоматически, llms.txt.
4. Антидубль: программные slug не должны пересекаться с блогом (SITE_MAP).

Покажи: сколько страниц сгенерируется (комбинаций), пример 1–2 готовых страниц, как растёт хвост.
```

> Важно для учеников: данных немного (10 услуг × 20 районов = 200 страниц), но механика — та же, что у 64K. Это «очень длинный хвост как у нас» в миниатюре.
