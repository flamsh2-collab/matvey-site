# GATE-проверки · сводка 7 этапов

> Каждый этап имеет жёсткую проверку. Не прошёл — чинишь, не идёшь дальше. Так фабрика держит качество на потоке (модель де́шева — качество в проверках).

| Этап | Что делаем | GATE (обязательно) |
|------|-----------|--------------------|
| 1 · Исследование | факты, источники, вопросы аудитории, гео-данные | ≥5 фактов с источниками + ≥3 вопроса для FAQ |
| 2 · Написание | черновик голосом компании по SEO-структуре | ≥1500 слов · H1×1 · H2/H3 ≥5 · FAQ ≥3 · CTA ≥2 · TLDR в первых 200 словах |
| 3 · Гуманайзер | убрать AI-следы (`HUMANIZER_БАНЫ.md`) | 0 HARD BANS · 0 стоп-слов компании |
| 4 · SEO | мета, slug, перелинковка, Schema (`SEO_ЧЕКЛИСТ.md`) | SEO-чек-лист зелёный · Schema валидна |
| 5 · Гео/GEO | локальные ключи + TLDR/FAQ/Schema под ИИ-поиск | TLDR отвечает на запрос · гео-ключ в title/H1 (для локального бизнеса) |
| 6 · Антидубль+вёрстка | проверка SITE_MAP, файл статьи, картинки | slug уникален · hero есть · картинки 200 |
| 7 · Деплой+индексация | build, публикация, проверка, пинг | статья открывается по URL (200) |

## Правила
- **Один провал = стоп.** Чинишь конкретный этап, не переписываешь всё.
- **Тренируй на себе:** первые 5–10 статей — с `REVIEW_BEFORE_PUBLISH=true`, читаешь глазами, правишь `company_voice.md`. Дальше — автопоток.
- **Лог на статью:** `pipeline/<slug>.md` — что прошло/не прошло (как у Кати).
- **Не публиковать без hero и без зелёного SEO-чек-листа.**
