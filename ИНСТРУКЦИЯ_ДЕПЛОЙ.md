# Инструкция · автодеплой статического сайта

> Цель: пуш в `main` → сайт сам пересобирается и выкатывается. Тогда скиллу достаточно закоммитить статью — она появится в интернете без ручных действий.

## Вариант A · Vercel (рекомендую для Astro/Next)
1. Залей репозиторий сайта на GitHub.
2. На vercel.com → New Project → импортируй репозиторий.
3. Framework определится автоматически (Astro/Next). Build: `npm run build`, output по умолчанию.
4. Deploy. Получишь публичную ссылку `*.vercel.app`.
5. Дальше любой пуш в `main` = автодеплой.
6. (Опц.) Привяжи свой домен в Settings → Domains.

## Вариант B · Netlify
1. Репозиторий на GitHub.
2. netlify.com → Add new site → Import from Git.
3. Build command `npm run build`, publish directory `dist` (Astro) / `out` (Next export).
4. Deploy → публичная ссылка `*.netlify.app`.

## Вариант C · GitHub Pages (бесплатно, без сторонних сервисов)
1. В репозитории — GitHub Actions workflow для сборки (Astro даёт готовый action).
2. Settings → Pages → Source: GitHub Actions.
3. Пуш в `main` → workflow собирает и публикует на `*.github.io`.

## Проверка
- Сделай тестовый коммит (правка в любом файле) → проверь, что деплой запустился и прошёл «success».
- Открой публичную ссылку — изменение видно.

## Оплата из РФ
Vercel/Netlify/GitHub Pages free-тарифа хватает для блога/контент-сайта. Платный тариф (если понадобится) — через pdpai.ru / WantToPayBot (как в М1).

> Если деплой не реагирует на пуш — проверь, что хостинг привязан к нужной ветке (`main`) и build не падает. Разбор — `../_ПОДДЕРЖКА/TROUBLESHOOTING.md`.
