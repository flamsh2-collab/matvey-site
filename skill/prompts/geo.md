# geo.md — этап 5 · две оптимизации

> «Гео» здесь = ДВА разных рычага. Применяй оба, если бизнес локальный; только второй — если бизнес не привязан к месту.

## 1. Географическая оптимизация (локальный SEO)
Для бизнеса с привязкой к городу/региону (недвижимость, услуги, офлайн).
```
- Гео-ключ в title + H1 (город/район/метро): «… в Петербурге», «новостройки Петроградского района».
- Отдельные страницы под гео-запросы: район, метро, город — у каждого свой URL и контент.
- Локальная конкретика: цены по локации, инфраструктура, время до центра, местные ориентиры.
- LocalBusiness / Place в Schema, если уместно. NAP (название-адрес-телефон) единообразно.
```

## 2. GEO — Generative Engine Optimization (под ИИ-поиск)
Чтобы статью цитировали ответы ИИ-поисковиков (Perplexity, Алиса, ChatGPT, AI Overviews).
```
- TLDR-блок в начале: прямой короткий ответ на запрос (ИИ берёт его в ответ).
- FAQ прямыми вопросами «как», «сколько», «что» + чёткие ответы.
- Факты с цифрами и датами (ИИ предпочитает верифицируемое).
- Schema (Article + FAQPage) — машиночитаемая структура.
- Списки и таблицы для «извлекаемых» ответов.
- Явные формулировки-выводы (ИИ цитирует утверждения, а не воду).
```

## 3. llms.txt — индекс для ИИ-поисковиков
Кроме разметки на странице — общий файл `public/llms.txt` (Markdown в корне сайта): краткое описание бизнеса + список ключевых разделов/статей со ссылками. ИИ-поисковики используют его как карту сайта «для ИИ». Обновляется при добавлении важных страниц (не весь сайт — кураторский индекс).

GATE: TLDR отвечает на запрос в первых 200 словах; для локального бизнеса — гео-ключ в title/H1; FAQ прямыми вопросами; `llms.txt` существует и пополнен.

> Контроль GEO (расширение): раз в неделю спрашивать у ИИ-поисковика твой запрос и смотреть, цитируют ли сайт (у Кати — «GEO Monitor» по понедельникам).
