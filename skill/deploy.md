# deploy.md — этап 7 · деплой + индексация

> По умолчанию автодеплой. Тумблер `REVIEW_BEFORE_PUBLISH=true` в `.env` → сначала показать черновики, ждать «ок».

## Шаги (как у Кати: build → проверка → индексация)
```bash
# 1. Сборка (должна пройти без ошибок)
npm run build              # exit 0; для больших сайтов: NODE_OPTIONS=--max-old-space-size=6144

# 2. Публикация — автодеплой хостинга по пушу в main
git add src/content/articles/ SITE_MAP.md
git commit -m "content: +N статей (SEO-завод)"
git push                   # Vercel/Netlify/GitHub Pages пересоберёт сайт

# 3. Верификация (после деплоя)
#   - статья открывается: curl -sI https://<сайт>/blog/<slug>/ → 200
#   - hero-картинка (og:image) отдаётся 200
#   - главная/каталог не сломались

# 4. Индексация
#   - пинг sitemap: https://<сайт>/sitemap.xml
#   - (опц.) Яндекс.Вебмастер «переобход» + Google Search Console «запросить индексирование»
```

## После деплоя
- Обновить `SITE_MAP.md` (новые slug+title) — антидубль на будущее.
- Обновить статус тем в `content_plan.html` → «опубликовано» + ссылка.
- Лог по каждой статье — `pipeline/<slug>.md`.

## Автодеплой сайта
Привязка репозитория к хостингу — `../ИНСТРУКЦИЯ_ДЕПЛОЙ.md` (Vercel / Netlify / GitHub Pages).

## Безопасный деплой (как deploy_safe.sh у Кати)
Перед раздачей — pre-checks: build дал ≥ ожидаемого числа страниц, HTTP 200 на главной, бэкап предыдущей сборки для отката. Если проверка не прошла — не выкатывать, откатиться.
